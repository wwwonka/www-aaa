## Pièges rencontrés (pour le prochain agent)

- **Garde de légèreté : mesurer sur le build PROD, pas en dev.** En dev, les imports
  `?worker&url` / `?url` de `ControllerHost` déclenchent des requêtes `render.worker` /
  `simulation.worker` / `Havok` (Vite construit le worker pour en donner l'URL). En **prod**
  (`vite preview`) ce sont de simples strings → **0 requête lourde**. Le smoke Playwright de
  légèreté doit tourner sur le build prod (c'est ce que fera la garde CI du PR 6).
- **`pnpm exec tsc` attrape le `tsc` homebrew obsolète** (`/opt/homebrew/bin/tsc`, TS 5.x) et se
  plaint des options de `tsconfig.json`. Typechecker avec `./node_modules/.bin/tsc --noEmit`
  (TS 6.0.3 local) — ou `pnpm build`.
- **`reconnecting`** : l'état de machine, le type de phase et le rendu overlay sont présents, mais
  le **lifecycle n'est pas câblé** (visibilitychange/pageshow/wakeLock) — c'est le PR 5, par
  conception, pour ne pas laisser de code mort.
