# 2026-07-11 — Controller mobile : routing, jeu solo, connectivité, shell DOM

## Fait

### Routing mobile + jeu solo (le bug rapporté)

- **Fix du bug** : un mobile en URL de base sautait direct en pairing plein écran.
  Cause : `roleFromPlatform` (`ContextManager.ts`) mappait `mobile → controller`, et
  `AppHost` envoyait `OPEN_PAIRING` à tout controller. Corrigé : `mobile` et `desktop`
  → `receiver` par défaut ; le rôle `controller` ne vient plus que d'un flag explicite
  (`?controller` / `?r=` d'un QR scanné).
- **Jeu solo mobile** : dérivé `selfControlled = platform mobile && role receiver`. Un
  mobile solo est à la fois l'affichage ET la manette (autorité locale permanente,
  `isLocalAuthority`). Débloque PLAY sans pairing. Vérifié bout en bout (START GAME →
  joysticks → le flock bouge, zéro pairing).
- **Item title « USE DEVICE AS CONTROLLER »** (mobile solo) : ouvre le scanner QR in-app,
  rejoint la room scannée à chaud en controller (`joinAsController`), `actingAsController`
  désarme l'autorité locale (l'input part en RTC).

### Connectivité cross-réseau

- **Signaling** : bascule Trystero `mqtt` → **`nostr`** (relais nativement wss/443 →
  joignables derrière les firewalls qui bloquent les ports MQTT 8084/8884). Vérifié :
  relais nostr se connecte, zéro erreur WS (l'ancien 8084 échouait).
- **ICE/TURN** : `rtcConfig.iceServers` branché sur `PairingChannel` + `getIceServers()`
  (`iceServers.ts`) — creds éphémères Cloudflare via `VITE_TURN_CREDENTIALS_URL`, fallback
  STUN public gratuit. **Worker Cloudflare scaffoldé** (`infra/turn-credentials/`, worker +
  wrangler + README) — l'utilisateur provisionne les secrets, rien de committé.
- **Scanner QR in-app** : `qrScanner.ts` (overlay DOM caméra) + décodeur **Nimiq
  `qr-scanner`** (lazy/code-split ~16 KB gz, `BarcodeDetector` natif quand dispo, worker
  fallback iOS). `extractRoomCode` isole le code depuis l'URL scannée.
- **Flow pairing structuré** : modèle d'état unique `PairingPhase`
  (searching/pairing/paired) possédé par `pairingHost`, poussé via `setPairingPhase`.
  Auto-pairing (scan = confirmation, pas de tap sur le receiver). Le controller se connecte
  dès qu'il découvre le receiver.

### Refactor UI : shell applicatif en DOM/CSS (Phases 1-2 sur 4)

Décision d'archi (voir `docs/decisions/2026-07-11-app-shell-dom.md`) : **le jeu +
title/pause restent en Pixi/Babylon (esthétique pixelisée) ; tout le shell applicatif passe
en DOM/CSS** (main thread). Motif : un controller pur ne devrait charger ni Babylon ni Havok.

- **Phase 1** — `ShellHost` (pendant DOM de `RenderManager`) + shell root par-dessus le
  canvas. **Toasts** et **RotateGate** (landscape) migrés en DOM. Supprimés (Pixi) :
  `ToastOverlayScreen`/`ToastPanel`/`ToastCard`/`RotateScreen` + APIs worker
  `showToast`/`setPortrait`. Vérifié.
- **Phase 2** — **Joysticks DOM dynamiques** (`Joysticks.ts`) : le stick apparaît sous le
  pouce là où le joueur touche, se replace si relevé ailleurs, deux pouces indépendants.
  Math lévée dans `input/stickMath.ts`. **Fix de l'inversion de l'axe vertical** (le stick
  vers le bas envoyait les boids vers le haut — désormais aligné sur la convention clavier
  de la sim, `ArrowUp` → z+). Supprimés : `GamepadScreen`/`VirtualStick` (Pixi). `pairingHost`
  expose `sendInput` en direct (plus de round-trip Comlink). Vérifié (solo).
- **Font** : le shell charge **fezbox** depuis le cache asset (servi par le SW depuis
  IndexedDB), `font-family: fezbox` sur tout le shell.

## Pièges pour le prochain agent/session

- **Non vérifiable en sandbox** : tout le round-trip de **pairing WebRTC** (découverte →
  paired → input) exige **2 devices réels** (ICE impossible entre deux contextes headless
  locaux). Le **scanner caméra** exige un **iPhone physique** (le Simulator iOS n'a pas de
  caméra). Charger le receiver sur l'**IP LAN** ou le tunnel (pas `localhost`, sinon le QR
  encode une URL injoignable depuis le tél.).
- **Flow controller** (START DOM après pairing, `setControllerMode`) : câblé, **non testé**
  (needs 2 devices). Le **solo** est pleinement vérifié.
- **Refactor DOM incomplet** : Phases **3 (pairing overlay → DOM)** et **4 (boot controller
  léger : pas de render worker/Babylon/sim)** restent à faire. La Phase 4 est LE vrai fix
  perf mobile. Aujourd'hui un controller spawne encore tout le stack ; pour éviter qu'il
  voie la scène title Babylon, `setControllerMode` est câblé mais il faudrait un black-cover
  DOM ou la Phase 4.
- **Handoff** (`HandoffCoordinator`, PLAY HERE / BRING IT BACK) : `setGamepadGameMode`
  devenu no-op (gameMode auto en DOM). À recâbler sur le shell au moment du handoff-in.
- **Asset loading** : pas encore séquencé par rôle. Piste discutée : joysticks en CSS/DOM
  (fait) permet à terme au controller de ne charger ni Babylon ni Pixi.
